# Maturity review record template

Copy for a real review; blank fields and proposed work do not count as evidence.
Use only consented, sanitized observations. Never include credentials, account
identifiers, private inputs or raw live responses. The
[governance rubric](../governance.md) defines each label.

- Experiment and concrete user task:
- Requested status; current status:
- Exact Lab / Kit revisions and date reviewed:
- Declared owner; accepted maintenance role or unassigned:
- Source provenance, redistribution rights and attribution:
- Runnable instructions, inputs, relevant tests and failure evidence:
- Access, costs, mode/platform limits and usage visibility:
- Human reproduction: non-author relationship, consented operator ID, date,
  environment, actual commands/exits, input/output checks, help and limitations:
- Maintenance acceptance: named person, scope, explicit acceptance/decision link:
- Host evidence, including failed/not-run cases; otherwise unverified:
- Graduation: need/reuse assessment, Kit PR/checks, versioned release/commit,
  attribution, Lab migration and affected regression results:
- Archive/downgrade: dated reason, last known result and replacement if available:
- Reviewer identity and role; distinguish human review from AI assistance:
- Decision (accepted / changes required / deferred), reason and missing evidence:
- Required documentation/manifest/catalogue changes and their PR:
- Follow-up owner and exact next action:

Mark inapplicable fields with a reason; do not dismiss a missing requirement as
inapplicable. Keep historical failed attempts and prior decisions linked.
